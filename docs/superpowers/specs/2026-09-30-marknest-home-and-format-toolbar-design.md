# MarkNest 主页与格式工具栏 —— 设计文档

- **日期**：2026-09-30
- **目标版本**：1.1.0（当前 1.0.2）
- **状态**：设计已确认，待转实施计划

---

## 1. 要解决的问题

当前应用打开后直接落在三栏视图，中间是一个**空编辑器**，屏幕上没有给出任何可做的事。新用户面对的是一句「未打开笔记」和一片空白；要开始写第一篇笔记，他得先自己发现顶栏那个 `＋`，或者去左侧目录树里点。

同时，编辑器虽然支持 Markdown 语法高亮，但**没有任何插入语法的手段**——写粗体要自己敲 `**`，写表格要自己对齐竖线。对一个笔记应用来说这是明显的能力缺口。

这一次要做两件事：

1. **给应用一个起始页**：打开就是主页，中间「打开文件 / 新建文件」，下方最近文件。
2. **给编辑器一条格式工具栏**：13 个按钮，覆盖常用的 Markdown 语法。

---

## 2. 已确认的决策

| # | 决策 | 选择 | 考虑过的其他方案 |
|---|---|---|---|
| 1 | 「打开本地电脑的文件」做什么 | **导入到笔记库**——本地文件成为一篇普通笔记 | ①只读打开、保存时下载副本（用户得自己替换原文件）②用 File System Access API 直接读写（TOS WebView 是否支持未知，需实测） |
| 2 | 「最近文件」按什么排 | **最近修改**（索引按 `mtime_ns` 倒序） | ①「最近打开」（需新增表 + 每次打开写入 + 清理策略）②两者混合（顺序会显得奇怪） |
| 3 | 主页占多大 | **占满整个工作区** | ①只占中间栏（主页会很挤，且「打开文件」与旁边的目录树功能重复）②占中间+右侧（收益不明显） |
| 4 | 截图里哪些要做 | **只要格式工具栏**，不做多标签页 | 两行都做（多标签会牵动视图模型：未保存提示、标签持久化、关闭确认，建议下一版） |
| 5 | 下划线按钮 | **去掉** | ①插入 `<u>` 并在预览消毒白名单里放行它（笔记内容是不可信输入，开 HTML 口子是实际代价）②换成删除线 `~~x~~`（语义上可行，保留了按钮位置） |

**决策 1 的理由**：浏览器无法凭空写回本地文件。导入让「笔记库是唯一事实来源」这条不变量成立——之后编辑、保存、搜索、快照保护的行为与库内笔记完全一致，不存在「这篇笔记存在哪」的第二种答案。

**决策 5 的理由**：Markdown 没有下划线语法（`_x_` 是斜体、`__x__` 是粗体）。既然预览已经把原始 HTML 关掉（`html: false` + DOMPurify），为一个按钮开一个口子不划算。

## 3. 视图模型

两个状态，由「有没有打开笔记」推出，不额外存储：

| 状态 | 何时进入 | 界面 |
|---|---|---|
| `home` | 启动时、点「主页」、关闭当前笔记 | 主页占满工作区，**无格式工具栏** |
| `note` | 打开任意一篇笔记 | 目录树 / 编辑器 / 预览，**编辑器上方多一条格式工具栏** |

**哈希路由**：`#/home` 与 `#/notes?p=<encodeURIComponent(路径)>`。这不是装饰——TOS 桌面可能在任意时刻重载 iframe，而 iframe 里没有地址栏，**哈希是唯一能存活的东西**，没有它重载后会静默回到空白。

## 4. 应用顶栏与「更多」菜单

**顶栏（`note` 与 `home` 共有，全应用唯一一条）**：

```
☰  [图标] MarkNest  v1.1.0        当前笔记路径            保存  预览  语言
```

- 左侧：**☰ 更多** + 品牌 + 版本徽标
- 中间：当前笔记路径（仅 `note` 态）
- 右侧：保存 / 预览开关 / 语言选择器
- **移除 `＋`**：它与菜单里的「新建文件」是同一件事，两个入口只会让人犹豫

> 「新建文件」此后仍有两个入口——**主页上的大按钮**和 **☰ 菜单**——这不是上面的重复问题。主页是起始页，在没有任何笔记打开时它需要一个明确的首选动作；而 `＋` 是顶栏里的**第三个**同类按钮，和菜单项并排出现，那才是犹豫的来源。判断依据是「同一个动作是否在同一屏里出现两次」。

**☰ 菜单**（点 `☰` 弹出）：**主页** · **新建文件** · **打开文件**。
复用目录树右键菜单已有的弹层样式与关闭逻辑（点击别处关闭），不引入新组件。

### 宿主几何约束

TOS 桌面把窗口家具**画在 iframe 之上**，顶栏最上面 **46px 整宽是窗口拖动带**（`.tos-dialog-move` 是 `width:100%; cursor:move`），那一块里的按钮点不动、且显示拖动光标。

当前顶栏内容从 y≈59 开始（`padding-top: calc(var(--host-band-top) + 12px)`），所以 ☰ 放在**工具栏最左侧**是安全的。`tools/measure_topbar.py` 会以**零相交**为断言兜底——不是「padding 等于 46」这种魔数匹配。

## 5. 主页

```
              【 打开文件 】    【 新建文件 】

   最近文件
     方案.md                          5 分钟前
     会议记录.md                      昨天
     读书笔记.md                      3 天前
```

- 两个大按钮居中
- 下方「最近文件」列表：标题 + 相对时间，点一条直接打开
- **空态**：库里还没有笔记时给一句引导（复用现有的空态样式，不新造）
- 最近文件为空但库非空（例如全部笔记都很旧）时不隐藏该区块，正常列出

**相对时间在前端算**：刚刚 / N 分钟前 / N 小时前 / 昨天 / N 天前 / 具体日期。

## 6. 格式工具栏

只出现在 `note` 态，位于应用工具栏**下方**、三个面板**上方**。离宿主拖动带很远，不涉及安全区问题。

**13 个按钮，分 4 组**（竖线为分组分隔）：

| 组 | 按钮 | 行为 |
|---|---|---|
| 1 行内 | **B** | 选中包 `**`；**已包裹则去掉**（切换语义）；无选中则插入 `****` 并把光标放中间 |
| 1 行内 | *I* | 同上，用 `*` |
| 1 行内 | `<>` | 同上，用 `` ` `` |
| 2 块级 | **```** | **代码块**：有选中 → 上下包三反引号围栏；无选中 → 插入三反引号 + 换行 + 光标 + 换行 + 三反引号 |
| 2 块级 | ❝ | 行首 `> `；已是引用则取消 |
| 2 块级 | H₁ H₂ H₃ | 行首 `# ` / `## ` / `### `；已是**同级**标题则取消；是其他级则替换 |
| 3 列表 | ☐ | **任务/清单**：行首 `- [ ] `；已是任务项则取消 |
| 3 列表 | • | **无序列表**：行首 `- `；已是无序项则取消 |
| 3 列表 | 1. | **有序列表**：行首 `1. `；已是有序项则取消 |
| 4 插入 | 🔗 | 有选中 → `[文字](URL)`，弹输入框只问 URL，确认后选中 `URL` 段便于改写；无选中 → 先问「显示文字」，再问 URL，插入 `[文字](URL)` |
| 4 插入 | ▦ | 插入 **3 列 × 2 行**（1 行表头 + 1 行分隔 + 1 行示例），光标落在第一个表头格内，便于直接输入替换 |

**为什么列表三项同组**：它们是对同一件事的三种选择（这一行怎么组织），放在一起用户才能一眼比较、来回切换；分散在两组里反而要来回找。

**为什么行内代码与代码块分属两组**：`<>` 改的是选中的几个字，``` 改的是整块结构，与标题、引用同类。放在一起会让人误以为它们是同一层的开关。

**切换语义统一规则**：所有按钮都是「再点一次撤销」。这一条要靠断言逐个钉住（§11 第 6 条），否则很容易只有一半按钮实现了切换。**例外是三个插入类按钮**：`codeblock`、`link`、`table` 只插入不撤销——上表中它们的行只描述插入什么，没有「已是…则取消」，因此只有其余十个按钮遵循本条。

> **关于截图里那个 `⇄` 图标**：设计初稿把它推断为「分割线」，但无法确认。评审时决定**直接去掉该按钮**——与其按猜测实现一个可能不是用户想要的按钮，不如不占这个位置；Markdown 的分割线 `---` 手敲三个字符即可。新增的「代码块」占用了一个空位，按钮总数仍为 13。

### 实现要点

**所有按钮必须走 CodeMirror 的 transaction API 派发，不得直接改 DOM。** 这是硬要求，不是风格偏好：

- 直接改 DOM 会绕过 CodeMirror 的 state，**撤销/重做会错乱**
- 变更不会触发 `updateListener`，于是**脏标记不亮**（改了却不提示未保存）
- 预览也不会刷新

三者（撤销栈、脏标记、预览）都挂在同一条 transaction 通路上，绕过去就会同时坏掉三个。

**行首类操作**（组 2、3）按行处理：取当前选区覆盖的所有行，逐行加/去前缀。**包裹类**（组 1）按选区处理，无选区时插入成对标记并把光标置于中间。

**工具栏按钮需要 14 语言工具提示**——应用要求 14 种语言的 `.lang`，WebUI 三语言；按钮 `title` 走现有的 `data-i18n-title` 机制，否则会变成「中文界面里混着英文 tooltip」这类已经踩过的缺陷。

## 7. 「打开文件」的两个来源

点「打开文件」→ 弹出选择器，两个来源。**选择器是一个弹层，两种来源在里面各是一个页签**——不能直接把用户丢给左侧目录树，因为从主页进入时目录树根本不在屏幕上（§3：主页占满工作区，没有三栏）。

| 页签 | 行为 |
|---|---|
| **笔记库（NAS）** | 弹层内渲染目录树（复用 `TreePane` 的渲染逻辑，作为选择器实例），选中即打开并关闭弹层 |
| **本机文件** | 浏览器文件选择器，选中的 `.md` **导入**到笔记库后打开 |

选择器复用现有的 `.modal` 弹层样式（NAS 选择弹窗在 1.0.x 已有成套样式与 Escape/点击遮罩关闭逻辑）。

### 导入流程

1. 读本地文件内容（`FileReader`）
2. `POST /notes/new {path, content}`
3. 若后端返回 `3006`（同名已存在），前端改名重试：`方案.md` → `方案-1.md` → `方案-2.md`（上限 100 次，防死循环）
4. 成功后打开该笔记

**约束**：大小沿用 `max_note_bytes`（8MB），超限由后端返回 `3008`；文件类型检查在前端做（只接受 `.md`/`.markdown`/`.mdown`/`.txt`），避免用户选了二进制文件后得到一个乱码笔记。

## 8. 后端新增

**只有一个端点**：

```
GET /recent?limit=N
  → { "notes": [ {path, title, mtime_ns, size}, ... ], "count": N }
```

- 按 `mtime_ns` 倒序，限当前用户
- `limit` 默认 12，上限 50
- **复用现有 `notes` 索引表，不新增表、不新增状态**（这是决策 2 换来的简化）
- 库不可读时抛 `3001`，与其余端点一致

在 `db.py` 的 `IndexStore` 上加一个 `recent(user, limit)` 方法；`api.py` 加一条路由。

## 10. 刻意不做（YAGNI）

| 不做 | 理由 |
|---|---|
| 多标签页 | 牵动视图模型（未保存提示、标签持久化、关闭确认），建议下一版单独做 |
| 「最近打开」 | 决策 2 选择了最近修改，不做第二套状态 |
| 下划线按钮 | Markdown 没有该语法，为它开 HTML 口子不划算 |
| 本地文件写回 | 导入即复制，笔记库是唯一事实来源 |
| 拖拽导入、多选导入 | 第一版用按钮足够 |
| 格式工具栏的可自定义 | 13 个固定按钮覆盖常用语法，配置界面是额外成本 |

## 11. 验证

### 离线（提交门槛）

`tools/verify_editor.py` 补充断言：

1. 启动后落在**主页**，不是空白编辑器
2. 「打开文件」「新建文件」两个按钮都在，且可点
3. 最近文件列表按修改时间倒序，点一条能打开对应笔记
4. ☰ 菜单展开后有「主页 / 新建文件 / 打开文件」三项
5. 从 `note` 态点「主页」能回到主页，且哈希变成 `#/home`
6. **13 个格式按钮每一个都产出正确的 Markdown**，且**每一个都能再点一次撤销**——分「有选区」与「无选区」两种情形逐个断言。其中代码块单独覆盖：无选区时插入的三反引号围栏内必须正好留出一行给光标；有选区时整段被围栏包住
7. **格式按钮的改动会让脏标记亮起**（这条直接钉住「走 transaction API」这个要求）
8. **导入一个本地文件后，它出现在库里且能打开**（模拟 `File` 对象）
9. 导入撞名时自动改名，不覆盖已有笔记
10. **窄宽度行为**：格式工具栏在放不下时**横向滚动**（不换行——换行会把编辑器挤下去，且工具栏高度变化会让编辑区跳动）；900px 以下隐藏预览（现有行为）；640px 以下隐藏目录树（现有行为）；主页的两个大按钮在窄宽度下**改为纵向堆叠**，最近文件列表保持单列

`tools/measure_topbar.py`：把主页按钮、☰ 菜单项、格式工具栏全部纳入扫描，8 个宽度下与宿主三段区域零相交。

`tools/webui_check.js`：`ORDER`/`MODULES`/`REQUIRED` 加入 `HomePane`、`FormatBar`；i18n 键集三语言对齐。

## 12. 版本

按项目约定递增 `VERSION`：**每次重新打包 +0.0.1**，本次从 `1.0.2` → **`1.0.3`**。`bump_version.py --bump patch` 同步 6 处派生字面量。

> 这一版功能不小（新增主页、格式工具栏、`/recent` 端点），按语义化版本可以论证成 `1.1.0`。但项目的既定规则是「每次重新打包 +0.0.1」，且 `bump_version.py --bump patch` 就是这条规则的实现——保持与工具一致，不在这里另立一套判断。
