# MarkNest 上架与审核

## 1. 提交流程

| # | 步骤 | 位置 |
|---|---|---|
| 1 | 注册开发者账号并实名认证 | 开发者平台 |
| 2 | 创建应用条目（**应用 ID 创建后不可更改**） | 应用信息页 |

## 2. 提交前本地自检（已内置）

```bash
python tools/validate.py            # 结构合规（72 项，含依赖契约与 bundle 门禁）
python tools/bump_version.py --check  # 版本号 6 处派生字面量一致
python tools/selftest.py            # 后端功能自检（51 项）
node tools/webui_check.js           # 前端跨模块调用 + i18n 键集对齐 + bundle 导出面
python tools/lang_stats.py          # 14 语言齐全 + 长度限制 + 漏翻检测
python tools/webui_build.py --check # 编辑器 bundle 与其源码一致
python tools/inspect_deb.py         # 产物结构、载荷位置与文件权限
python tools/build.py               # 打包（内部先跑 validate）

# 以下需要 Playwright
python tools/verify_editor.py       # 编辑/预览/保存/冲突/消毒/滚动同步
python tools/measure_topbar.py      # 交互控件与宿主三段区域零相交
```

上述自检全部须返回退出码 0。

## 3. ⚠️ 本应用必须主动声明的三件事

审核方不会自己知道这些，**不主动说明就会被当成缺陷**。

### 3.1 应用会写入共享文件夹（这是功能本身）

与只读类应用不同，MarkNest **必须**写入共享文件夹——它的全部功能就是编辑笔记。

| 审核提问 | 答复 |
|---|---|
| 写的是哪个文件夹？ | 只有它自己创建的那一个：`/Volume*/marknest-data`，由 `postinst` 调用平台工具 `ter_share_add -owner marknest` 建立 |
| 会不会碰我的其它共享文件夹？ | 不会。`preinst` **刻意不加入 `allusers`**，因此应用账户对操作者的其它共享文件夹没有任何访问权 |
| 会不会改共享文件夹的权限？ | 不会，也不尝试。应用从不调用任何 ACL 修改接口 |
| 会不会删我的笔记？ | 只有用户自己在界面里确认删除时才删。**卸载应用时任何参数下都不删该文件夹**（见 3.2） |
| 会不会把笔记内容传到别处？ | 不会。全部处理在 NAS 本地，无任何外发请求 |

### 3.2 卸载不删除笔记（刻意偏离惯例）

`DEBIAN/postrm` 在 `remove` 与 `purge` 下**都不删除** `/Volume*/marknest-data`。

**理由**：那些是用户自己的文件，不是本包的运行时状态；而且平台的 `ter_share_add` **没有配套的删除工具**，删了就找不回来。删掉一个人的笔记，只因为他卸载了一个应用，是不可辩护的。

**请审核方注意**：这不是漏写的清理，而是有意为之。

### 3.3 每用户隔离由代码实现，不是操作系统

服务以单一非特权账户运行，用户身份来自 `tos_current_username` cookie。

**如实说明**：该 cookie 由客户端提供。已经持有有效平台会话的人可以把 cookie 指向另一个用户名，从而访问那个人的笔记库。

**这是平台模型的属性，不是本应用引入的**：服务只有一个 unix 账户，操作系统同样无法区分二者。应用内部的缓解是严格校验（字符集 + 必须解析出真实系统账户），真正的修法只能来自平台提供「按应用、按用户」的身份。

**给操作者的建议**：若多人共用且互不信任，请在控制面板收紧 `marknest-data` 的 SMB 访问。

## 4. 规范对照

### 4.1 一票否决项

| # | 项 | 本应用 |
|---|---|---|
| V1 | 不得以 root 运行 | `config.ini.user = "marknest"`，systemd `User=marknest`，双重校验通过 |
| V2 | `config.ini` 语法 | JSON、双引号、无注释、无尾逗号、无单引号、无全角引号 |
| V3 | 14 种语言 | 齐全（`lang_stats.py` 校验） |
| V4 | 名称与描述非空 | 通过 |
| V5 | 架构一致 | `platform: x86_64` ↔ `control.Architecture: amd64` |
| V6 | 元数据位置 | `usr/local/marknest/` 内 |
| V7 | 行尾 | 全 LF（构建时强制并复检） |
| V8 | 无明文凭据 | `validate.py` 扫描通过 |

### 4.2 自动化检查

| 域 | 本应用 |
|---|---|
| config.ini | 必填字段齐、无保留字段、键全小写、`id` 字符集、分类白名单、`iframe` 禁 `open_path`、`recommend:false`、`low_version ≥ 7.0` |
| 语言文件 | 长度 64/512/512/2048、除 `</br>` 外禁 HTML、UTF-8 无 BOM |
| 图标 | SVG 含 `viewBox`、透明背景 |
| systemd | 非 root 且与 `config.ini.user` 一致；**禁命名空间指令**（`/var` 是符号链接会导致 `226/NAMESPACE`）；`StartLimitBurst=10`/`IntervalSec=120`；包内 `init.d/` 与 `/etc/systemd/system/` 逐字节一致；`ExecStart` 指向已打包文件 |
| control | 必填字段、声明 `python3`、无 nodejs/JRE/Go 硬依赖、包名一致 |
| 生命周期脚本 | 无网络安装、LF + bash shebang、`chmod -R u=rwX,go=rX`、**升级时清 `__pycache__`**、**断言服务真的起来了** |
| iframe 载荷 | `webui.bz2` 已打包，`index.html` 在顶层 |
| 载荷权限 | 数据 0644 / 可执行 0755，无组或其他用户可写 |
| 端口 | 仅 Unix Socket，无 TOS 保留端口 |
| 架构 | 载荷无 ELF |

### 4.3 人工复核关注点

| 关注点 | 本应用 |
|---|---|
| 功能真实性 | 描述中提到的 Markdown 编辑、实时预览、全文搜索、冲突检测均在代码中实现 |
| 能力边界如实 | 未声称「自动发现笔记」或「多端同步」等不存在的能力 |
| 权限最小化 | 不加入 `allusers`、不申请特权、不改 ACL、不落凭据 |
| 用户数据声明 | 见 §3.1，且已如实说明写入行为 |
| 输入校验 | 路径在进入文件系统前收窄（拒绝绝对路径、`..`、符号链接、控制字符、超长名），并通过 `realpath` 双侧包含性校验 |
| 依赖合理性 | 仅 `python3` + `systemd` 硬依赖，无非预装件 |
| 数据合规 | 笔记仅存 NAS 本地，无外发 |
| 资源占用 | 索引为 30 秒低频扫描；无常驻高 CPU |
| 错误处理 | 结构化错误码（3xxx 域）+ 按码本地化的前端提示，不静默失败、不泄漏英文原句 |
| 文档完整性 | `docs/开发文档.md` 含部署前置条件 |

### 4.4 编辑器 bundle 的特殊说明

`webui/js/vendor.editor.js` 是**开发机预构建并提交进仓库**的产物（CodeMirror 6 + markdown-it + DOMPurify，697 KB）。因为部署目标不允许运行时存在 Node：

- `tools/build.py` **绝不调用 Node**
- `Depends` 保持 `python3, systemd`
- `validate.py` 断言载荷内**不含** `webui-src/`、`package.json`、`node_modules/`
- `validate.py` 重算源码哈希，源码改了但没重新构建即判定失败

## 6. 常见驳回原因与规避

| 驳回原因 | 本应用如何规避 |
|---|---|
| 元数据无法解析 | 元数据在 `usr/local/marknest/` 内，不在 deb 根 |
| 应用无法启动 | 构建时强制 LF 并复检 CRLF |
| 接口 404 | 后端接受三种路径前缀，`selftest` 覆盖 |
| 安装失败 | 无非预装件硬依赖 |
| 安装后无图标 | `icon` 字段与磁盘文件名双向校验 |
| 语言审核不通过 | `lang_stats.py` 预检长度与漏翻 |
| 以 root 运行 | `user` 字段 + systemd `User=` 双重校验 |
| **应用自动停用** | 单元内无命名空间指令；`validate.py` 硬校验；启动限流放宽至 10/120 |
| 重装后故障复发 | 包内 `init.d/` 副本与 `/etc` 保持字节级一致 |
| 界面白屏 | 前端 `step()` 隔离各启动步骤，单个失败不会中断整体 |
| 载荷权限过宽 | 打包器显式赋模式 + `postinst` 整树规范化 + `inspect_deb.py` 阻断 |
| 中文界面出现英文 | 按错误码本地化，英文仅作未知码兜底；`webui_check.js` 校验键集对齐 |
| 顶栏控件重叠/点击偏移 | 交互控件不进入宿主三段区域，`measure_topbar.py` 零相交断言 |
| 改了但真机没变化 | `?v=` 由 `VERSION` 派生，改代码必须递增版本号 |
| 版本号多处漂移 | `VERSION` 唯一来源，`--check` 作提交门槛 |
| **构建产物静默过期** | 编辑器 bundle 的源码哈希门禁（`webui_build.py --check`） |
| 用户不知如何恢复能力缺失 | 笔记库不可用时给出明确原因与恢复路径；`3001` 提示「在应用中心重新安装」 |
| 界面状态与后端相反 | 能力探测一律来自**真实尝试操作**，不从 `stat`/模式位推断 |

## 7. 版本迭代约定

1. **单一事实来源**：版本号只写在仓库根目录 `VERSION`，其余 6 处由 `tools/bump_version.py` 派生
2. **递增是硬性要求**，同时也是前端缓存失效的**唯一**手段——`?v=` 不变则 WebView 复用旧资源
3. **前端改动若涉及 `webui-src/`，必须重新运行 `tools/webui_build.py`**，否则 `validate.py` 会判定失败
4. 每次提交前执行 §2 的全部自检，须零错误
5. `release_note` 按序号追加，不改写历史条目
